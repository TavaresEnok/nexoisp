# B10 — confiança SSH, capacidade e resultado desconhecido

Código no agente, sem mudança de schema/dependências/UI. Não houve conexão com equipamento físico ou serviço produtivo.

- `nexo_agent/ssh_trust.py`: known_hosts local explícito, com permissões restritas; ausência recusa conexão. Netmiko usa `ssh_strict=True`, arquivo alternativo e nenhum trust automático/sistema. Chave divergente é recusada antes da senha. RSA/SHA-1, KEX SHA-1, MACs antigos e cifras CBC antigas desabilitados; RSA/SHA2 continua possível com chave RSA >=2048. Firmware legado que só oferece algoritmo bloqueado permanece incompatível, sem fallback.
- Instalação/rotação offline: `python -m nexo_agent.ssh_trust --known-hosts /data/ssh/known_hosts --host HOST --public-key 'TIPO CHAVE_PUBLICA' --fingerprint SHA256:VERIFICADO --reason 'Motivo verificado pelo operador'`; rotação exige também `--previous SHA256:ANTERIOR`. Não busca chave na rede. Diretório deve existir, ser privado; não usa private key. Compare fingerprint por canal independente. Registro intent fsync precede troca atômica/fsync; committed segue depois. Journal `.audit.jsonl` contém somente material público/ator local/motivo. Interrupção exige conferir journal e arquivo; não apagar pin para aceitar outra chave. Entrada compartilhada por aliases exige separação explícita, sem remover pin de outro host.
- Factory real Huawei exige `known_hosts_file` nas credenciais locais. Escrita fica desligada por padrão (`allow_writes` só aceita booleano true) e exige `expected_product`/`expected_firmware` explícitos. Antes de cada mutação lê modelo/firmware sem aproveitar cache de heartbeat e compara exatamente. Isso expressa aprovação local, não homologação automática. Construtor de driver com transporte injetado continua disponível para fixtures, sem seletor remoto de emulador.
- Consultas com permissão negada, serial divergente, service-port desconhecido ou saída incompleta não viram ONU ausente/lista vazia. Somente mensagens de ausência conhecidas são aceitas. F/S/P é validado antes de compor outra consulta. VLAN/GEM são validados antes de escrita. Não há criação/exclusão de perfis compartilhados.
- Envelope ONU vincula marcador à identidade/versão assinadas. Executor compara descrição completa e se recusa a adotar/remover ONU de outro recurso. Uma falha definida de comando ainda permite reconvergência da própria configuração; timeout/EOF após mutação vira AckLost.
- Tentativa ONU interrompida não vira NOT_APPLIED por leitura momentaneamente negativa. Permanece durável e só confirma por readback positivo, sem reenviar. Nova operação no mesmo recurso é recusada enquanto outra tiver efeito desconhecido, inclusive se mudar versão/equipamento; não substitui o registro local da ONU. Não foi criado atalho para apagar incerteza.
- RouterOS: transporte inseguro (plaintext/skip verify) exige flag explícito `NEXO_AGENT_ALLOW_INSECURE_LAB=1` **e IP literal de loopback**. Use túnel de laboratório quando necessário, não libere insegurança para IP de equipamento. TLS verifica CA/hostname e mínimo 1.2. Erro após remover sessão é classificado como confirmação perdida, para leitura pelo executor.

Credencial ilustrativa (valores reais não fornecidos): `known_hosts_file=/data/ssh/known_hosts`, `allow_writes=false`; quando houver aprovação de bancada, preencher produto/firmware observados exatamente e aprovar escrita localmente. Não é necessário habilitar escrita para diagnosticar identidade/modelo. Nenhum desses flags foi habilitado nesta entrega.

Verificação Linux/Python 3.12 isolada, Docker network none (apenas loopback): 23 testes dirigidos de confiança/Huawei/ONU/NAS aprovados, mais asserção adicionada de bloqueio por recurso e teste de handshake contra servidor somente RSA/SHA-1. Não somar repetições como cobertura nova. Chave incorreta e algoritmo legado foram recusados antes de autenticação; rotação auditada preservou outro host; emulador exercitou leitura e recuperação. Código instalado Netmiko 4.5.0/Paramiko 3.5.0 foi inspecionado antes de alterar parâmetros; lock não mudou.

**C/T locais; H/P não realizados.** Não é prova de compatibilidade Huawei/MikroTik físicos. Dependem de bancada: versões reais, negociação permitida, fixture CLI e tempos/readback. Ainda faltam fluxos administrativos de adoção/resolução com prova para resultados que permaneçam desconhecidos; permanecer bloqueado é comportamento deliberado. Não considerar todo B10, rede ou projeto concluído.
